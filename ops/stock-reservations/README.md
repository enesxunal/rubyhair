# Stock reservation worker

New checkouts reserve stock for 30 minutes. The dedicated endpoint checks expired reservations without initiating captures, shipments or email. A provider-confirmed terminal unpaid reservation is released atomically; CREATED, approved, captured, unknown and HTTP 404 cases remain held for manual reconciliation. This is deliberately not an unconditional 30-minute cancellation. Existing reservation deadlines are preserved.

Deploy after the parallel payment changes are merged and independently tested. Set a dedicated random STOCK_RESERVATION_CRON_SECRET in the Vercel production environment. Provision the same secret through a root-owned mode-0600 curl config at /etc/rubyhair/stock-reservations.curl (header = "Authorization: Bearer <secret>"), never in git or logs. Verify unauthenticated requests return 401. Install the service/timer in /etc/systemd/system, daemon-reload, validate the timer and enable it only after confirming production uses the merged build. Check the response counters (checked, cancelled, held) and reconcile held orders individually. Do not run the general customer-jobs endpoint every five minutes: that can also send mail or run fulfillment. The worker limits a single sweep to ten orders; monitor held backlog and review old ambiguous records before rollout. Rollback: disable the timer and revert the isolated commit; do not reverse verified stock releases blindly.
